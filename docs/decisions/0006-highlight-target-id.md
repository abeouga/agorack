# 0006 強調する場所の ID を、部品に依らない名前（targetId）にする

- 状態：検討中（未決定）
- 日付：2026-11-14

この記録はまだ決まっていない。下の「案」は、枝 `refactor/embed-highlight-target-id` で試しに実装したもの。決めるときは「決めるときに確かめること」をすべて埋めてから、状態を「決定」に変える。

## 決めること

Agorack から部品の埋め込み用の画面へ送る `agorack:highlight` について、次の2つ。

- 強調する場所の ID を、何という名前にするか
- 名前を替えるあいだ、名前を替える前の部品の画面をどう動かし続けるか

## 背景

- `agorack:highlight` は、強調する場所を `fieldId`・`fieldIds` という名前で送っている（[0005](0005-evidence-panel-document-pane.md)）。中身は「部品が決めた ID」で、Agorack は解釈しない。それなのに、名前は帳票の言葉（欄＝field）になっている。
- これから走行の記録の部品（カブロガー）の画面も埋め込む予定で、走行で強調するのは欄ではなく区間になる。このままでは、どの部品にも共通の契約に文之助の言葉が残る。
- 部品と Agorack は別々のリポジトリで、別々に直して出す。文之助の埋め込み用の画面は、いまも `fieldId`・`fieldIds` を読んでいる。Agorack だけが名前を替えると、文之助の画面で強調が効かなくなる。

## 選択肢

**名前**

| 案 | 長所 | 短所 |
|---|---|---|
| `targetId`・`targetIds` | 「強調する的」という意味だけを持ち、欄にも区間にも使える | 少し抽象的 |
| `locationId`・`locationIds` | 根拠の `location` と結び付く | `location` はオブジェクトで、その中の ID とまぎらわしい |
| `fieldId` のまま | 何も変えずに済む | 共通の契約に部品の言葉が残る |

**替え方**

| 案 | 長所 | 短所 |
|---|---|---|
| しばらく新しい名前と古い名前の両方を送り、部品が新しい名前を読むようになったら古い名前を消す | どちらを先に出しても、強調が止まらない | 移すあいだ、契約に古い名前が残る |
| Agorack と文之助を同時に替える | 契約がすぐきれいになる | 片方だけを出すと強調が止まる。別々に出せるという、部品に分けた理由に反する |

## 案（試しに実装したもの）

1. 強調する場所の ID の名前を `targetId`（選んだ場所）・`targetIds`（同じ記録の根拠の場所の全部）にする。上限の定数も `HIGHLIGHT_TARGET_IDS_MAX`・`HIGHLIGHT_TARGET_ID_MAX_LENGTH` にする。上限の値（500 個・1〜200 文字）は変えない。
2. 移すあいだ、Agorack は古い名前の `fieldId`・`fieldIds` にも同じ値を入れて送る。契約では古い名前を、なくてもよい項目として残し、移行用と書いておく。`targetId` のないメッセージは受け付けない。
3. 部品は `targetId`・`targetIds` を読むように直す。すべての部品が直したら、Agorack は古い名前を送るのをやめ、契約から消す。
4. 根拠から強調する場所の ID を取り出すのは、Agorack の画面の1か所（`embedTarget.ts` の `rawTargetIdOf`）だけにする。いまは書類の根拠の `location.field_id` を読んでいる。

## 決めるときに確かめること

- [ ] 名前を `targetId` にするか、ほかの名前にするか
- [ ] 替え方を「しばらく両方を送る」にするか
- [ ] 古い名前を消す条件と時期（文之助の埋め込み用の画面が新しい名前を読むようになり、それが出たあと、など）
- [ ] 下の「残る課題」（根拠の外枠に強調する場所の ID を持たせるか）を、この記録で一緒に決めるか、別の記録に分けるか。一緒に決めるなら、名前はそちらの形に合わせる
- [ ] 文之助の側の対応（`frontend/src/embed/embedChannel.ts` が新しい名前を読む）を、文之助のリポジトリの Issue にしたか

## 影響（案のとおりに決めた場合）

- `packages/contracts`：`HighlightMessageSchema` を `targetId`・`targetIds` にし、移行用の `fieldId`・`fieldIds` を残す。
- Agorack の画面：送るメッセージに新旧の両方の名前を入れる。偽の埋め込み用の画面は新しい名前を読む。
- 文之助：埋め込み用の画面が `targetId`・`targetIds` を読むようにする（文之助のリポジトリで扱う）。それが出たら、Agorack の側で古い名前を消す。

## 残る課題

Agorack の画面が根拠の `location.field_id` を読んでおり、「Agorack は `location` を解釈しない」という根拠の約束に、まだ1か所だけ反している。カブロガーを足す前に、部品が根拠の外枠に強調する場所の ID を入れて返す形を決める（[次に決めること](../open-questions.md) の 1）。
