# 0007 帳票の値は欄の条件で引き、ベクトル検索の索引は作らない

- 状態：決定
- 日付：2026-11-14

## 決めること

答えに使う部品の値を、どうやって取り出すか。部品の道具（MCP の tool）で欄の条件を指定して引くか、文章を埋め込みのベクトルにして意味の近さで探すか（ベクトル検索の RAG）。

## 背景

- 文之助が返すのは、人が確認して確定した帳票の値で、「欄の名前と値」の組になっている。
- 質問には、件数・合計・平均を正確に求めるもの（例：「毛色が黒の牛は何頭か」）が多い。
- 答えには、どの書類のどの欄から取った値かを示し、右の欄で強調する（[0003](0003-sources-via-mcp.md)・[0005](0005-evidence-panel-document-pane.md)）。
- 値は文之助の確認画面で直されることがある。Agorack は値を直さず、部品の中にも手を入れない（[設計](../architecture.md) §3）。

## 選択肢

| 案 | 長所 | 短所 |
|---|---|---|
| 部品の道具で欄の条件を指定して引く（`search_documents`・`get_document`・`aggregate`） | 条件に合うものを漏れなく返せる。件数・合計を部品の側で正確に出せる。根拠を欄の単位で返せる。直した値がそのまま返る | 欄の名前を先に調べる往復が要る。表記の揺れや言い換えに弱い。自由に書いた文章は探しにくい |
| Agorack にベクトル検索の索引を作る | 言い換え・表記の揺れに強い。欄の名前を知らなくても当たりを付けられる。部品をまたいで探せる | 上位の何件かしか返らないので、件数・合計が取りこぼしで合わなくなる。文章を切ると、どの欄から取ったかが薄れる。値を直すたびに索引を作り直す必要があり、古い値で答えるおそれがある。部品のデータを Agorack に写すので、部品の中に手を入れない約束に反する。埋め込みのモデル・保存先・更新の処理が増える |
| 部品の中にベクトル検索を作り、MCP の道具として出す | 部品の中に閉じるので、つなぎ方の約束を守れる。言い換えや自由記述の文章に対応できる | 部品の側に索引とその更新の処理が要る。件数・合計には使えない |

## 決定

1. 最初の版では、答えに使う値は部品の道具で欄の条件を指定して引く。数の計算は部品の道具（文之助の `aggregate`）に任せる。
2. Agorack にはベクトル検索の索引を作らない。部品のデータを Agorack に写して持たない。
3. あとで言い換えや自由に書いた文章（備考など）を探す必要が出たら、ベクトル検索は部品の中に作り、MCP の道具として出す。その道具は「当たりを付ける」ためだけに使い、件数・合計は今までどおり欄の条件で引く道具で求める。

## 影響

- Agorack に埋め込みのモデル・ベクトルの保存先・索引の更新の処理は要らない。
- 質問の言葉と欄の値の表記が違うと、当たらないことがある。そのときの言い換えは Claude が欄の名前と値の候補を見て行う。
- ベクトル検索の道具を足すときは、部品の側の作業になる。Agorack は設定と道具の説明（部品の `instructions`）が増えるだけで、会話のループは変えない。
