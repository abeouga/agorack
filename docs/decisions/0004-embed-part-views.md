# 0004 右の欄に部品の画面を iframe で埋め込む

- 状態：決定
- 日付：2026-11-09

## 決めること

右の欄で根拠（書類のどの欄か、など）を見せるとき、何を表示するか。部品の画面を埋め込むなら、その住所を根拠のどこに持たせるか。

## 背景

- 書類の見え方（ページ・欄の枠・表の行）は部品ごとに違い、いちばんよく知っているのは部品自身である。
- Agorack が部品ごとの表示を作り込むと、部品が変わるたびに Agorack も直すことになり、「部品が増えても Agorack の中心は変えない」（設計 §3）に反する。
- 文之助の今の確認画面は修正・確定の操作を含むので、そのまま埋め込むと Agorack から値を直せてしまう（設計 §3「値を直さない」に反する）。

## 選択肢

**表示の仕方**

| 案 | 長所 | 短所 |
|---|---|---|
| 部品の埋め込み用の画面を iframe で出す | 部品の表示をそのまま使え、部品ごとに別々に直せる。Agorack は部品の中身を知らずに済む | 部品の側に、見るだけの画面と埋め込みの許可が要る |
| Agorack がページ画像に枠を描く | 部品の側に画面が要らない | 部品ごとの表示を Agorack が作り込むことになる |
| 部品の画面のコードを Agorack のビルドに取り込む | 見た目をそろえやすい | 部品のコードを import することになり、境界が崩れる |

**埋め込みの住所の置き場所**

| 案 | 長所 | 短所 |
|---|---|---|
| 根拠の外枠に `embed_url` を足す | 画面は部品を区別せず「`embed_url` があれば iframe」で出せる。カブロガーも同じ形で足せる | 根拠の外枠の約束（0003）を直す |
| `location` の中に置く | 外枠の約束は変わらない | 画面が kind ごとに `location` の中を読むことになる |
| Agorack が部品の URL の形を知って組み立てる | 部品の MCP を変えずに済む | 部品の仕様を Agorack に書くことになる |

## 決定

1. 右の欄は、部品の「埋め込み用の画面」を iframe で出す。埋め込めないとき（`embed_url` がない・部品が止まっている）は、`kind` ごとの表示（書類ならページ画像に枠）に戻す。
   - 2026-11-10 追記：右の欄の組み立て（外の枠は Agorack が描き、iframe は枠線なしで中いっぱいに置く。根拠の一覧は答えの下へ移す）と、postMessage の `fieldIds`・`embed:close` を足した。理由と使い方は [0005](0005-evidence-panel-document-pane.md)。
2. 部品の MCP は、根拠の外枠に `embed_url` を付けて返す。Agorack の型では `embedUrl` と呼ぶ。
3. 埋め込みを許す住所は、Agorack では部品の設定（`embed.origin`）に、部品では `Content-Security-Policy: frame-ancestors` に書く。どちらにもない住所とは、埋め込みも postMessage もしない。
4. 埋め込み用の画面は見るだけにし、修正したいときは部品の普通の画面を別のタブで開く。
5. 作る順番は、チャットとページ画像の表示が通しで動いてから（設計 §1 の段階 2）。

## 影響

- 文之助の側に、埋め込み用の画面・埋め込みの許可・根拠の `embed_url` の作業が要る（文之助のリポジトリの Issue で扱う）。
- Agorack の側は、契約（`embedUrl`・postMessage のメッセージ）、部品の設定（`embed.origin`）、右の欄の `renderers/embed/` を足す。
- ページ画像に枠を描く表示は、埋め込めないときの表示として残る。
- ログインがある部品（Cognito など）を埋め込むときのログインの状態の受け渡しは、次の版で考える。
