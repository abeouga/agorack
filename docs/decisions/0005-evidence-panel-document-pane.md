# 0005 右の欄を「書類の欄」1枚にし、根拠の欄の一覧を埋め込みに渡す

- 状態：決定
- 日付：2026-11-10

## 決めること

右の欄を、文之助のチャットの右の「書類の欄」（`AskPage.tsx` の `DocumentPanel`）と同じ見た目にする。そのための、右の欄の組み立てと、埋め込み用の画面とのやり取り（postMessage）の形。

## 背景

- 右の欄は「根拠」の見出し → 「文之助の画面」の文字 → 枠付きの iframe → 根拠の一覧、の順に積んでいる。iframe の中の文之助の画面にも枠があり、枠が入れ子になっている。
- 文之助のチャットでは、書類の欄はチャットと一続きの1枚の枠で、境目のつまみで幅を変えられる。中は書類の表示（`PageViewer`）1枚だけで、根拠の欄はまとめてオレンジで強調し、選んだ欄をさらに強くする。
- 埋め込み用の画面（`/embed`）は書類の全部の欄を薄く描き、選んだ1つだけを青い線で囲む。答えの根拠がどれかを知っているのは Agorack だけなので、根拠の欄の一覧は Agorack が渡す必要がある。
- 埋め込み用の画面は見るだけにし、修正は部品の普通の画面を別のタブで開く（[0004](0004-embed-part-views.md)）。

## 選択肢

**根拠の欄の一覧の渡し方**

| 案 | 長所 | 短所 |
|---|---|---|
| `agorack:highlight` に、なくてもよい `fieldIds` を足す | 1つのメッセージで「どれを強調し、どれを一番にするか」が決まる。`fieldIds` がなければ今と同じに動く | ready の前は一覧を渡せない（ready のあとすぐ送る） |
| URL に `fields=` を足す | 最初の表示から強調できる | 答えが替わるたびに iframe を読み直すことになり、住所が長くなる |
| 新しいメッセージ `agorack:evidence` を足す | 役目が分かれる | 2つのメッセージの順番を考えることになる |

**外の枠を描く側**

| 案 | 長所 | 短所 |
|---|---|---|
| Agorack が外の枠を描き、iframe を枠線なしで中いっぱいに置く | 埋め込めないときの表示も同じ枠に入る。チャットと一続きの境目・つまみを Agorack が持てる | 部品の画面の中を「枠の中身だけ」にしてもらう必要がある |
| 部品の画面が外の枠まで描く | 部品の側だけで見た目が決まる | Agorack のチャットとの境目やつまみを部品が描けない |

## 決定

1. 右の欄は「書類の欄」1枚にする。外の枠（枠線・角の丸み・チャットと一続きの境目・幅を変えるつまみ・padding 12px）を Agorack が描き、中に部品の画面（iframe、枠線なし）か、埋め込めないときの `kind` ごとの表示を置く。
   - 2026-11-10 追記：文之助のチャットの書類の欄は、あとの指定で外の枠の padding を 0 にしており、12px は書類の画像のまわりの余白だった。見た目をそろえるため、外の枠の padding は 0 にし、余白は中の表示が持つ（[architecture.md §7.3](../architecture.md)）。
2. 「根拠」の見出しと根拠の一覧は、右の欄から外し、答えの下に移す。
3. `agorack:highlight` に、なくてもよい `fieldIds`（この答えの根拠のうち、同じ記録の場所の ID の全部。上限 500 個）を足す。Agorack は `embed:ready` を受けたあとと、根拠が替わったときに送る。
4. 部品 → Agorack に `{ type: "embed:close" }` を足す。部品の画面の × で右の欄を閉じる。
5. 「部品で開く」は残す。部品の画面の中で、× の左のアイコンのボタンにする（文之助のチャットの書類の欄との違いは、ここだけ）。
6. 右の欄は、答えに根拠があるとき自動で開く（文之助のチャットは表の行を押したときに開くが、Agorack は根拠を見せることが役目のため）。× で閉じ、表の行や答えの下の根拠を押すと開き直す。

## 契約の細かい決まり

- `fieldIds` は文字列の配列で、上限は 500 個、1つの ID は 1〜200 文字。`fieldId` も同じく 1〜200 文字にする。
- `fieldId`（選んだ場所）は `fieldIds` に含めて送る。部品は `fieldIds` をまとめて強調し、`fieldId` をさらに強くする。
- `fieldIds` がないときは、部品は `fieldId` だけを強調する（`fieldIds` を足す前と同じ動き）。
- 部品は、この形に合わないメッセージを丸ごと捨てる。一部の ID だけを使うことはしない。
- 形は `packages/contracts/src/embed.ts` に置き、zod で検証する。

## 影響

- `packages/contracts`：`HighlightMessageSchema` に `fieldIds`、`EmbedToAgorackMessageSchema` に `embed:close` を足す。
- Agorack の画面：右の欄の外の枠、答えの下の根拠の一覧、埋め込めないときの表示、`fieldIds` の送信と `embed:close` の受信を、それぞれ別の Issue で作る。
- 文之助：根拠の欄をまとめて強調すること（abeouga/fuminosuke#69）と、埋め込み用の画面を「枠の中身だけ」にして × と「文之助で開く」を置くこと（abeouga/fuminosuke#70）を、文之助のリポジトリの Issue で扱う。
- 書類の欄の中で値を直すことはしない（見るだけのまま、[0004](0004-embed-part-views.md) の決定 4）。
